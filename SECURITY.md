# Безопасность

Приложение обрабатывает чувствительные семейные сведения локально. Отсутствие
облака не отменяет необходимости защищать компьютер и резервные копии.

## Сообщение об уязвимости

Не публикуйте эксплойт с настоящими семейными данными или секретами в обычном Issue.
Используйте **Security → Report a vulnerability**, если эта возможность включена
в репозитории. Если её нет, создайте Issue только с просьбой предоставить приватный
канал связи — без деталей уязвимости, персональных данных и вложений.

Сообщите версию, ОС, условия эксплуатации и минимальный синтетический пример.
Подтверждённого SLA или отдельной службы поддержки у проекта пока нет.

## Перед публикацией данных

- SQLite, фото, JSON/GEDCOM, плакаты и логи могут идентифицировать родственников.
- Не добавляйте их в Git или публичные Issues, даже если файл кажется тестовым.
- `.gitignore` не удаляет файл, уже попавший в историю.
- Не публикуйте ключи подписи и пароли; для CI используйте GitHub Secrets.
- В случае утечки секрета сначала отзовите его, а затем займитесь очисткой истории.

# Самостоятельная публикация на GitHub

## 1. Проверьте исходники

```powershell
npm run check:publication
node scripts/check-publication.mjs --history
git status --short
```

Скрипт не открывает игнорируемые семейные базы: он проверяет только Git-видимые
исходники. Дополнительно просмотрите картинки, исходники, изменения и авторов
коммитов. Проверка не является DLP-системой или гарантией отсутствия утечек.

Не загружайте `data/`, `photos/`, `migration/`, `backups/`, `research/`, `exports/`,
`test-results/`, базы, GEDCOM, логи, токены и ключи. Не снимайте эти исключения
ради публикации. Установщик размещайте в Releases, а не в истории исходников.

Обратите внимание: локальная история разработки может содержать прежний README
с локальными путями и email автора в метаданных. Изменение текущего README или
настройки `user.email` не меняет прошлые коммиты. Не используйте `git push --all`
или `git push --tags`, если не проверили каждую ветку и метку.

## 2. При желании создайте чистую публичную копию

Рекомендуемый вариант для первого публичного выпуска: текущие исходники без
локальных баз и без старой истории. В рабочем проекте:

```powershell
node scripts/prepare-public-folder.mjs ..\family-atlas-desktop
cd ..\family-atlas-desktop
```

Скрипт **не перезаписывает существующую папку**, не меняет исходный репозиторий,
не создаёт коммит и ничего не загружает в сеть. Он копирует только проверенные
Git-видимые файлы и создаёт новый локальный Git-репозиторий `main`.

Настройте автора. Для приватности скопируйте собственный `noreply`-адрес из
**GitHub → Settings → Emails**:

```powershell
git config user.name "YOUR_GITHUB_LOGIN"
git config user.email "YOUR_NOREPLY_EMAIL_FROM_GITHUB"
git add .
git commit -m "Initial public release"
```

Замените оба значения своими. Не публикуйте действующий личный email, если хотите
сохранить его приватность. Параметр `private: true` в `package.json` запрещает
случайный выпуск в npm и не мешает публичному GitHub-репозиторию.

## 3. Создайте пустой публичный репозиторий

1. На GitHub нажмите **+ → New repository**.
2. Имя: **family-atlas-desktop**.
3. Выберите **Public**.
4. **Не добавляйте** README, `.gitignore` и лицензию через форму: они уже есть в исходниках.
5. Нажмите **Create repository** и скопируйте HTTPS-адрес.

MIT распространяется на код. Перед публикацией проверьте разрешения на фон и
значки: отдельный статус изображений описан в [NOTICE.md](../NOTICE.md).

## 4. Отправьте исходники

В чистой публичной папке после первого коммита:

```powershell
git remote add origin https://github.com/YOUR_GITHUB_LOGIN/family-atlas-desktop.git
git push -u origin main
```

Замените `YOUR_GITHUB_LOGIN`. При первом `push` Git Credential Manager может открыть
вход через браузер. Пароль GitHub в терминале не заменяет HTTPS-авторизацию Git;
используйте вход через менеджер учётных данных или токен, введённый только локально.
Никогда не вставляйте токен в URL remote или в файлы проекта.

Если `origin` уже существует, сначала проверьте `git remote -v`. Не заменяйте его
вслепую. Если удалённый репозиторий создан с файлами или содержит чужую работу,
не делайте `push --force`: согласуйте историю или создайте действительно пустой репозиторий.

## 5. Проверьте GitHub и добавьте установщик

1. Убедитесь, что README отображается, лицензия определяется как MIT, а Actions запускается.
2. Проверьте, что баз, реальных фото и экспортов на странице Code нет.
3. Откройте **Releases → Draft a new release**.
4. Для этой версии создайте тег **v0.1.0** на публичной `main`.
5. Заголовок: **Семейный атлас 0.1.0**.
6. Прикрепите только установщик из рабочей сборки:
   `src-tauri/target/release/bundle/nsis/Семейный атлас_0.1.0_x64-setup.exe`.
7. Укажите: Windows x64; пакет пока не подписан; нужен WebView2; семейные данные не включены.
8. Просмотрите релиз и опубликуйте, когда готовы.

GitHub сам приложит архив исходников. Не прикладывайте полный каталог проекта,
каталог данных приложения или ZIP с настоящим семейным деревом. После первой
успешной CI-сборки можно добавить соответствующие пакеты macOS/Linux, не выдавая
непроверенный запуск за протестированную платформу.
